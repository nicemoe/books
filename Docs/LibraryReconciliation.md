# 书库启动与文件对账

前台事件只通过 `BookshelfView.task(id: scenePhase)` 调用 `reconcileFiles()`。
一个文件操作状态串行保护对账、导入和章节重建；不再同时维护两组忙碌布尔值。

1. `BookDisk.snapshot()` 一次枚举读取名称、大小和修改时间。扫描失败直接报告，不能用不完整目录推断书籍被删除。
2. `BookReconciliation` 根据快照生成新增、删除、正文变更和仅元数据变更的计划。
3. 大小、时间、分章版本都没变时，不读正文、不算摘要、不重新分章，也不显示解析进度。
4. 时间改变但大小相同时，比较持久化 SHA-256；内容相同只更新修改时间，正文真正变化才重建。
5. 写入正文后清除 URL 属性缓存，记录实际的新文件状态。摘要直接由已生成的 UTF-8 数据计算。
6. 导入及重建必须等待书目索引原子写入完成才报告成功。文件错误逐项报告；保存失败不会推进写入版本号。

旧索引没有内容摘要。如果文件修改时间也已经不一致，无法证明原章节对应当前正文，需要重建一次建立摘要；后续未修改的书复用索引。
当前策略使用文件大小、修改时间作为快速检查，因此外部工具同时修改内容并刻意保留大小及修改时间的情况不会被发现。

回归测试覆盖 1000 本书连续三次对账不读取正文、新增/删除/等长修改/只改时间的分类、文件读取失败、旧分章规则迁移、保存后重开、缓存属性失效和写入失败后同版本重试。
这些是 macOS 上编译生产辅助组件的测试；iOS App 另外通过完整归档验证，手机现有书库仍需升级后确认。
